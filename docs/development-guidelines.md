## 3. Documentation & Context Management

The `docs/` directory contains the project's reference documents. These documents are the source of truth for project requirements, design decisions and development standards.

### Documentation References

| Document | Purpose |
|---|---|
| `docs/assignment.txt` | Assignment requirements, features, pages and functionality. |
| `docs/design-system.md` | Brand identity, visual design, colors, typography and UI components. |
| `docs/development-guidelines.md` | Coding standards, components, state management and implementation workflow. |

### 3.1 Assignment Requirements

Before implementing a feature, read the relevant sections of `assignment.txt`.

Use the following section references:

- Sections 1–3: Project overview, technology stack and project structure.
- Sections 4–5: Public website, authentication and authorization.
- Sections 6–7: Customer and admin dashboards.
- Sections 8–10: Appointment booking, payment and profile management.
- Sections 11–12: Loading, error handling, notifications and UI quality.
- Sections 13–15: Challenges, database architecture and security.
- Sections 16–18: README, GitHub, submission and deployment.
- Sections 19–22: Development principles, testing checklist and final submission details.

Always check the specific requirement before implementation. Do not implement unrelated features.

### 3.4 Context Management Rules

- Read only the documentation sections relevant to the current task.
- When a task involves both functionality and UI, consult the relevant assignment and design-system sections together.
- Follow development guidelines throughout implementation.
- Use section numbers and headings to locate the exact information needed.
- Do not unnecessarily repeat or copy documentation into prompts or other files.
- Treat the current user prompt as the scope of the task.
- Do not invent missing requirements or design decisions.
- If documentation conflicts or important information is unclear, ask the user before making significant decisions.
