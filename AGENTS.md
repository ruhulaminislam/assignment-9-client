## 3. Documentation & Context Management

The `docs/` directory contains the project's reference documents. Use them as the source of truth throughout development.

### Documentation References

| Document | Purpose |
|---|---|
| `docs/assignment.txt` | Complete assignment requirements, features, pages and functionality. |
| `docs/design-system.md` | Approved visual design, logo, colors, typography, components and UI guidelines. |
| `docs/development-guidelines.md` | Coding standards, component structure, state management, hooks and implementation workflow. |

### Documentation Rules

- **Assignment Requirements:** Before implementing a feature, locate and read the relevant section(s) in `assignment.txt`. Follow the original requirements and section references.
- **Design References:** When creating or modifying UI, locate and follow the relevant section(s) in `design-system.md`. Do not introduce unapproved design decisions.
- **Development Rules:** Follow the relevant guidelines in `development-guidelines.md` throughout implementation.
- **Section References:** Use section numbers and headings to identify the exact information needed. Do not rely only on document names.
- **Cross-Reference:** When a task involves both functionality and UI, check the relevant assignment and design-system sections together.
- **Focused Reading:** Read only the relevant sections needed for the current task. Read additional sections only when necessary.
- **No Duplication:** Do not copy the full contents of these documents into `AGENTS.md` or duplicate their rules unnecessarily.
- **Source of Truth:** Do not invent missing requirements, features or design decisions. If documents conflict or important information is unclear, ask the user before proceeding.
